# Project canvas

A project brings a browser tab group together in a persistent workspace. Its canvas provides a shared view of the group's pages, with space to explore each page and selected excerpts.

The canvas has two complementary views: the pages themselves and a combined topic tree built from saved article topics. The combined tree preserves links to source articles and sentences, so readers can move from shared themes back to their evidence. Project chat answers questions across the project's pages and does not need the tree: it works as soon as the project has one readable page. Its pages are the project's open tabs plus its saved pages (which cover a closed tab group), without duplicates; tabs that are not web or file pages are listed to the assistant as unreadable. With no pages the panel only says there is nothing to chat about. Every question triggers a relevance check: code re-reads every page and asks, page by page over all of its lines, whether and where that page helps answer the question (the chat's earlier questions are passed along so follow-ups resolve). By default the completion LLM judges each page; when a decision provider is chosen in Options → LLM Providers → "Project chat page scan", it answers typed relevance questions about the page's passages instead, and a page whose check fails is marked unknown while the rest continue. The panel shows "Checking pages for relevance…" with a count while this runs. The results go to the assistant with the page list, with the relevant page lines quoted word for word (as much as fits the context budget) rather than summarised, so small details such as numbers, names or exceptions reach it. It can read further: `read_page` reads a page from a given line, `search_page` finds keywords in one page or all pages, and `ask_pages` repeats the relevance check for a different sub-question. It highlights the page lines its answer relies on: each highlight is a chat event that names the page and keeps a copy of the cited lines. Nothing is added to the canvas until a highlight is picked in the chat's Events tab: then one "Chat evidence" card shows its lines, stacked under its page's card after its excerpts and linked to it like an excerpt, but unsaved. It has no chat or Delete, only a close button; picking another event replaces it, and it also goes away when a new turn or chat starts or the chat panel is hidden. It also cites the pages it read in prose, by title and line numbers. When a merged topic tree has been built, it is an additional source: the assistant also gets the topic search, read and claim-source tools over it. Page and excerpt chats remain scoped to their own content. They can highlight passages of it, and picking one of those events in the chat's Events tab unfolds a temporary evidence card under the drawer showing the cited lines; it is not saved and closes when another event is picked, the selection is cleared, or the chat is folded. In the combined tree, each source card also has a Chat tab: its chat is scoped to that text, and the assistant can read and search the full source article behind it. A topic's "Source text" block gathers the text of everything under it, grouped by sub-topic and article, and its chat can read and search every article it quotes.

Projects persist beyond a browser session and can be reopened from the project list. When their source pages change, the combined tree can be refreshed to reflect the current material; existing article records remain independent.

The [summary tree](15-summary-tree.md) describes the shared topic-tree approach. The main code entry points are the [project page](../src/project/main.jsx) and the [project topic tree](../src/project/ProjectTopicTree.jsx).

Topic merging is optional for project chat: without a finished merge the chat panel offers a short hint and a button to start one, and with a merge that is out of date it keeps answering from the current pages and flags that the tree is from the saved merge. Topic merging runs as a project-owned background job. Readers can switch between Canvas and Topics, close the project view, or read source pages while it continues. Checkpoints and results are saved to the project, and running merges automatically resume after a background worker or browser restart. Reopening the project shows the saved progress or completed tree; Stop explicitly cancels processing.
